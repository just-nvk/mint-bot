# Мята · запись — Telegram-бот для записи в салон

Демо-проект [nvk](https://just-nvk.github.io/): салон «Мята» вымышлен, код и тесты настоящие.
Видео и короткая сводка — на [странице кейса](https://just-nvk.github.io/cases/mint-bot/).

## Что умеет

- **Запись без звонков.** Услуга → день → время → подтверждение. Цены видны на кнопках, бот показывает только свободное время и сам выбирает свободного мастера.
- **Напоминания.** Накануне в 18:00 и за 2 часа до визита, с кнопками «Да, приду» и «Перенести».
- **«Мои записи».** Клиент сам переносит или отменяет запись.
- **Администраторы в курсе.** О каждой записи, переносе и отмене бот пишет в рабочий чат с кнопкой «Написать клиенту». Команды `/today` и `/tomorrow` показывают расписание на день.

## Быстрый старт

Нужен Python 3.11+.

```sh
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env               # впишите BOT_TOKEN от @BotFather
python -m mint_bot
```

Чтобы приходили уведомления администраторам, добавьте бота в рабочую группу и отправьте там `/chatid`. Бот ответит ID группы — впишите его в `.env` как `ADMIN_CHAT_ID` и перезапустите бота.

## Настройка салона

Всё, что меняется без программиста, лежит в `salon.toml`: услуги и цены, длительность, мастера, часы работы и перерывы, выходные, время напоминаний, лимит записей на клиента. После правки перезапустите бота.

## Как устроено

```
mint_bot/
  handlers/      Telegram: разбирают нажатия и показывают шаги
  booking.py     сценарии: запись, перенос, отмена, списки
  domain.py      правила расписания — чистые функции без Telegram и базы
  storage.py     SQLite: записи и очередь напоминаний
  reminders.py   воркер, который раз в 30 секунд отправляет наступившие напоминания
  notify.py      уведомления в чат администраторов
  texts.py       все тексты бота
  keyboards.py   кнопки и данные в них
  config.py      .env и salon.toml
```

Зависимости идут в одну сторону: `handlers → booking → domain, storage`. Правила расписания тестируются без Telegram, а сценарии — без сети.

## Ключевые решения

- **Выбор клиента хранится в кнопках, а не в памяти.** Услуга, день, время и мастер зашиты в `callback_data`. После перезапуска бота любая кнопка в чате продолжает работать.
- **Напоминания — строки в базе, а не таймеры в памяти.** Они переживают перезапуск. Если бот лежал и наступили оба напоминания сразу, придёт одно — с правильным «сегодня» или «завтра». Если визит уже начался, напоминание не отправляется.
- **Двойной записи не бывает.** Проверка свободного времени и запись — одна транзакция. Кто нажал «Подтвердить» вторым, увидит «Это время только что заняли» и актуальные слоты. Повторное нажатие той же кнопки не создаёт вторую запись.
- **Время в базе — в UTC, на экране — в часовом поясе салона.** Пояс задаётся в `salon.toml`.
- **Тексты бота = тексты видео.** `tests/scenario.json` — тот же файл, по которому собрано демо-видео. Тест проходит сценарий целиком и сравнивает каждое сообщение и каждую кнопку.
- **Закрытый профиль клиента не ломает уведомления.** Telegram не пропускает сообщение с кнопкой-ссылкой на такого пользователя. Тогда бот отправляет уведомление без кнопки, а имя клиента делает упоминанием.

## Тесты

```sh
pip install -r requirements-dev.txt
pytest
```

37 тестов, меньше секунды, без сети: вместо Telegram — тестовая сессия, которая записывает запросы бота и даёт нажимать кнопки.

Что проверяется:
- сценарий из видео — слово в слово;
- сетка времени, перерыв, выходные, запас в час до начала;
- двое записываются на одно время одновременно — проходит только один;
- перенос и отмена: время освобождается, напоминания пересчитываются;
- напоминания после перезапуска, после простоя, после начала визита, при блокировке бота и сбое сети;
- кнопки «Назад» и «Изменить», устаревшие кнопки, лимит записей, команды администратора.

Тесты и линтер (`ruff`) запускаются на GitHub при каждом пуше — см. `.github/workflows/tests.yml`.

## Запуск на сервере

Пример для Linux-сервера с systemd:

```sh
sudo useradd --system --home /opt/mint-bot mint
sudo git clone https://github.com/just-nvk/mint-bot /opt/mint-bot
cd /opt/mint-bot
sudo python3 -m venv .venv
sudo .venv/bin/pip install -r requirements.txt
sudo cp .env.example .env && sudo nano .env
sudo chown -R mint:mint /opt/mint-bot
sudo cp deploy/mint-bot.service /etc/systemd/system/
sudo systemctl enable --now mint-bot
journalctl -u mint-bot -f          # логи
```

База — файл `data/mint.db`. Для резервной копии достаточно копировать его.

## Ограничения

- Один процесс бота на одну базу. Для нескольких копий бота нужна PostgreSQL.
- У мастеров общий график — часы работы салона. Личные графики и отпуска — следующий шаг.
- Нет онлайн-оплаты и синхронизации с CRM или календарём.
- Телефон клиента бот не спрашивает: связь — через Telegram.
